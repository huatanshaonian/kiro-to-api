## 上下文窗口与启动失败修复（2026-10-30）

早期启动器固定 100K compact 窗口，网关也保留 128K 的本地策略预算。
真实使用中，提示词与完整工具目录的首轮输入已接近 50K，CC 在约 65K
发生自动压缩。现将默认 compact 窗口与网关预算改为 1M；网关保留 16K
输出空间，输入仍按本地估算检查。CC 自身会扣除内部预留空间。
自动压缩验收脚本显式使用隔离的 100K/10% 测试配置，不影响日常入口。

长输入实测：1,020,199 字符，本地估算 350,100 tokens；Kiro 成功完成，
报告 context_usage_percentage=36.2008，首/中/尾三个随机标记均保留。
这证明已突破原 128K 本地限制，不代表测定了上游最大窗口。

本机 2.36.0 更新入口出现 Windows access denied，未进入模型请求；
已安装的实际 2.35.1 执行文件在相同请求下成功。生产通过现有
KIRO_CLI_PATH 显式固定已验证的实际版本，保留原入口和程序文件。
启动错误现在优先显示真实错误行与退出码，不再由管理员提示遮蔽原因。
